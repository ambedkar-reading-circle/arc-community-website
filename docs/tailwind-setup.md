# Manual steps: Install Tailwind CSS v4 in this Hugo repo

This guide adds Tailwind CSS v4 to the site without changing the architecture:
`assets/css/main.css` stays the **source** stylesheet (still git-tracked), the
Tailwind CLI compiles it to `assets/css/tw.css` (generated, git-ignored), and
Hugo's existing asset pipeline (`resources.Get | minify | fingerprint`) keeps
serving it. No Hugo theme, no PostCSS, no Node bundler in the page.

How the pieces fit at dev time:

```
Terminal 1:  npm run css:watch      assets/css/main.css  ->  assets/css/tw.css
Terminal 2:  hugo server -D         assets/css/tw.css    ->  /css/tw.<hash>.css
```

Production: `npm run css:build` first, then `hugo --minify`, then deploy `public/`.

---

## 0. Prerequisites

Check Node.js is available (Tailwind v4 CLI needs Node 20+; Wrangler already
requires Node, so it is probably installed):

```powershell
node -v
npm -v
```

Check Hugo is the extended build (you already use it for `minify | fingerprint`):

```powershell
hugo version
```

---

## 1. Create `package.json` and install Tailwind

Run from the repo root (`D:\ARC\arc-community-website`):

```powershell
npm init -y
npm install --save-dev tailwindcss @tailwindcss/cli
```

This creates `package.json`, `package-lock.json`, and `node_modules/`.

---

## 2. Add npm scripts

Edit `package.json` and replace the generated `scripts` block with:

```json
"scripts": {
  "css:watch": "tailwindcss -i assets/css/main.css -o assets/css/tw.css --watch",
  "css:build": "tailwindcss -i assets/css/main.css -o assets/css/tw.css --minify"
}
```

> The command is `tailwindcss`, not `@tailwindcss/cli`. npm names the
> `node_modules/.bin` shims after the package's `bin` field, and
> `@tailwindcss/cli` declares its binary as `tailwindcss`. The package name
> form only works through `npx` (e.g. `npx @tailwindcss/cli -i ...`), which
> resolves package -> binary; a bare command in a script does not.

- `css:watch` — development: rebuild `tw.css` whenever `main.css` or any
  template class changes.
- `css:build` — production: same, minified, no watcher.

---

## 3. Turn `assets/css/main.css` into the Tailwind input file

Replace the contents of `assets/css/main.css` with:

```css
/*
 * SOURCE stylesheet — edit this file, never assets/css/tw.css.
 * Compiled by: npm run css:watch  (dev)  /  npm run css:build  (prod)
 */
@import "tailwindcss";

/* Design tokens (docs/design.md) exposed as Tailwind utilities:
   bg-primary, text-primary, from-primary, font-heading, ... */
@theme {
  --color-primary: #131857;
  --color-background: #ffe;
  --color-text: #1a1a1a;

  --font-heading: "Miriam Libre", sans-serif;
  --font-body: "Miriam Libre", sans-serif;
  --font-fallback: system-ui, -apple-system, sans-serif;
}

/* Plain CSS still works below — Tailwind passes it through unchanged. */

* { box-sizing: border-box; }

html { color-scheme: light; }

html, body { height: 100%; margin: 0; }

body {
  font-family: var(--font-body);
  line-height: 1.6;
  background: var(--color-background);
  color: var(--color-text);
}
```

Notes:

- The old `body { display: flex; align-items: center; ... }` centering is
  deliberately dropped — it would fight the full-viewport split layout in
  step 7. The old `main.uc` card styles are replaced by utilities there too.
- Anything inside `@theme` becomes a real Tailwind token, so the utilities
  you write stay in sync with `docs/design.md`.

---

## 4. Point `baseof.html` at the compiled file

In `layouts/_default/baseof.html`, change the pipeline line to read `tw.css`:

```html
{{ $css := resources.Get "css/tw.css" | minify | fingerprint }}
<link rel="stylesheet" href="{{ $css.RelPermalink }}">
```

(One word changes: `main.css` -> `tw.css`. The Google Fonts `<link>` lines
above it stay exactly as they are.)

---

## 5. Ignore generated files in git

Append to `.gitignore`:

```gitignore
# Node / Tailwind
node_modules/

# Generated by Tailwind CLI from assets/css/main.css
assets/css/tw.css
```

Ignoring `tw.css` also matters for Tailwind v4's automatic content detection:
git-ignored files (including all of `public/`) are excluded from class
scanning, so deleted classes really disappear from the output.

---

## 6. Run both watchers and verify

Terminal 1:

```powershell
npm run css:watch
```

Wait until `assets/css/tw.css` exists. Terminal 2:

```powershell
hugo server -D
```

Verify, in order:

1. `assets/css/tw.css` exists and contains a big block of generated CSS.
2. Open `http://localhost:1313/`, view source, confirm the stylesheet URL is
   `/css/tw.<fingerprint>.css`.
3. Temporarily add `class="text-primary"` to the `<h1>` in
   `layouts/index.html`, save, and confirm the color applies. Remove it after.

If the page has no styles, see Troubleshooting below.

---

## 7. Build the split home page

One half scrollable, the other half a fixed viewport-height gradient block
whose width is controllable per breakpoint.

Replace `layouts/index.html` with:

```html
{{ define "main" }}
<div class="flex h-dvh flex-col overflow-hidden font-body md:flex-row">

  {{/* Half 1 — scrollable content */}}
  <section class="flex min-h-0 flex-1 flex-col items-center justify-center px-6 py-10 overflow-y-auto">
    <main class="uc w-full max-w-3xl text-center">
      <h1 class="font-heading font-bold tracking-tight text-primary text-[clamp(1.75rem,5vw,2.5rem)]">
        {{ .Title }}
      </h1>
      <div class="msg text-[1.05rem]">{{ .Content }}</div>
    </main>
  </section>

  {{/* Half 2 — fixed gradient block, width controlled by viewport */}}
  <aside class="h-[40vh] w-full flex-none bg-linear-to-br from-primary via-indigo-700 to-sky-500
                md:h-auto md:w-1/2
                lg:w-[58%]
                xl:w-2/5">
  </aside>

</div>
{{ end }}
```

How it satisfies each requirement:

| Requirement | Utilities used |
|---|---|
| Two halves of the viewport | `flex h-dvh` (+ `md:flex-row`; stacks vertically on mobile) |
| Half 1 scrolls | `overflow-y-auto` on the section — scrolls *inside* its pane; `min-h-0` is required or flex children refuse to overflow |
| Half 2 fixed at viewport height, never moves | it is a sibling of the scrolling pane inside `h-dvh overflow-hidden`, so it stays put; `flex-none` stops it shrinking |
| Gradient | `bg-linear-to-br from-primary via-indigo-700 to-sky-500` (v4 syntax; `from-primary` comes from the `@theme` token) |
| Width controlled by viewport width | `md:w-1/2` -> `lg:w-[58%]` -> `xl:w-2/5` — pick any values; arbitrary widths like `w-[38vw]` also work |

Tuning knobs:

- **Which side**: put the `<aside>` first and add `md:order-last` to it (or
  wrap with `flex-row-reverse`).
- **Gradient direction**: `bg-linear-to-b` (top->bottom), `bg-linear-to-r`,
  `bg-linear-to-br`, ...; drop `via-*` for a two-stop gradient.
- **Colors**: `from-primary to-transparent`, or arbitrary hex with
  `from-[#131857]`.
- **Mobile height of the gradient block**: change `h-[40vh]`, or use
  `hidden md:block` to remove it entirely on small screens.

The old `main.uc` CSS from step 3 was removed, so all card styling now comes
from the utilities written on the elements themselves.

---

## 8. Production build and deploy

Build order matters — Tailwind first, Hugo second:

```powershell
npm run css:build
hugo --minify
```

Then deploy `public/` as usual (Wrangler, per `wrangler.jsonc`:

```powershell
npx wrangler deploy
```

`css:build` minifies, and Hugo's pipeline still fingerprints, so the final
URL is cache-busting safe: `/css/tw.<hash>.css`.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Blank page, no CSS URL in source | `assets/css/tw.css` doesn't exist yet — run `npm run css:watch` (or `css:build`) before/alongside Hugo. `resources.Get` returns nil and the `<link>` is dropped. |
| Class changes don't appear | Is `css:watch` still running? Did you edit `main.css` (source), not `tw.css` (generated)? |
| Deleted classes stay in output | They are being scanned from somewhere. Confirm `public/` and `assets/css/tw.css` are git-ignored (step 5). |
| `bg-gradient-to-r` does nothing | v4 renamed gradients to `bg-linear-to-r`. |
| Gradient pane pushes page taller than screen | The wrapper must keep `h-dvh` (or `h-screen`) and `overflow-hidden`, and the scrolling pane needs `min-h-0`. |
| `@tailwindcss/cli: No such file or directory` | The package's binary is named `tailwindcss` — use that in scripts (or prefix with `npx`). |
| Styles fine locally, missing after deploy | Deploy ran `hugo` without a fresh `css:build`. Always build CSS first. |
